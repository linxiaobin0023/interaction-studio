# 人物—奶嘴交互一致性优化 · 产品原型开发映射说明

## 1. 本轮整改结论

本版原型按正式实施方案与最新评审意见补齐以下产品能力：

- Business Attempt / Infrastructure Retry 的显式状态与计数；
- Formal Freeze 只读纪律；
- Case Base Readiness Gate、Asset Readiness Manifest 与 Cure Period 异常态；
- Preflight Gate 红黄绿与 Formal No-Go 决策支持；
- Repair Evaluation：Attempt 1 Pass、U_max、Measured Repair Uplift、Cluster Bootstrap CI；
- Placement Sensitivity → Operation Accuracy 看板；
- Gold Case 参考层；
- Material Class / Transmission / Specular；
- Product Mask 分层 Debug；
- Model License / Production Eligibility；
- Asset Graph、Atomic Event、Hash Chain、Formal Evidence Package、Replay。

## 2. 明确不进入产品 UI 的内容

评审报告提出 TCO / Lean / Platform Gate。

**本产品原型不加入该功能。**

原因：TCO、交付模式属于项目实施与商业治理，不属于“人物—奶嘴交互一致性生产系统”的用户业务功能；产品 UI 只保留项目生产、算法、测试、证据与质量相关能力。TCO 继续保留在实施方案/项目管理材料中。

## 5. Attempt 状态机

```text
CREATED
→ PREPARED
→ INFERENCE_STARTED
→ INFERENCE_SUCCEEDED
→ OUTPUT_PERSISTED
→ VALID_OUTPUT
```

只有 `VALID_OUTPUT` 消耗 Business Attempt。

```text
max_business_attempts = 2
max_infra_retry_per_attempt = 2
```

Infra Retry：

- GPU OOM
- Worker Crash
- HTTP 5xx
- Provider Timeout
- Object Storage Failure

Infra Retry 不扣 Business Attempt；超过 Retry 上限进入 `SYSTEM_FAIL`。

## 6. Formal Freeze

Frozen Build 后：

- Case 只读；
- 不允许删除 Formal Case；
- 不允许修改 Prompt / Model / Workflow / Template；
- 不允许新增 Business Attempt；
- 不提供 Case 级“重新生成并调参”的入口。

后端建议字段：

```json
{
  "dataset": "FORMAL",
  "frozen": true,
  "frozen_build_id": "build-8f3d92a",
  "allow_case_mutation": false,
  "max_business_attempts": 2
}
```

实体建议：

## 8. Repair Evaluation

建议接口：

```text
GET /api/analytics/repair-evaluation?interaction=MOUTH
```

返回：

```json
{
  "attempt1_pass_rate": 0.44,
  "u_max_pp": 17.6,
  "measured_uplift_pp": 12.0,
  "cluster_bootstrap_ci_pp": [7.0, 16.0],
  "gate_pp": 8.0,
  "decision": "GO"
}
```

如果 `u_max_pp < 8`：

```text
NO_GO_REPAIR
```

UI 展示推荐路径，不自动修改 Formal Case 分布。

## 9. Operation Accuracy

来源必须是 Gold Case / Sensitivity Study。

```json
{
  "center_error_p80": 0.041,
  "center_gate": 0.05,
  "rotation_error_p80_deg": 5.2,
  "rotation_gate_deg": 7,
  "scale_error_p80": 0.063,
  "scale_gate": 0.08,
  "expert_brush_rate": 0.12

```

生成工作台只展示当前安全性；技术分析页展示统计来源。

# 14. 本轮评审增量

## Attempt / Formal
- `Business Attempt = 2/2` 时 UI 显示 `Final`。
- `Infra Retry >2` 自动进入 `SYSTEM_FAIL`，生成入口禁用。
- Formal QC 为只读；开发/验证 Case 才可在 QC 页面改判。
- Frozen Formal Case 的编辑、删除、追加 Attempt 必须由后端权限同时拦截，不能只靠前端隐藏。

## Gate / No-Go
- Hand 等 `CONDITIONAL` Gate 必须返回 `blocking_conditions[]`。
- No-Go 页面状态必须直接订阅同一 Gate Result 数据源，禁止前端维护第二份状态。
- No-Go Report 可导出，用于评审存档。

## Cure Period
```json
{
  "status": "ACTIVE",
  "started_at": "...",
  "deadline_at": "...",
  "remaining_seconds": 223200,
  "missing_assets": ["F018-BASE","F023-BASE"],
  "available_actions": ["SUPPLEMENT","BASE_GENERATION","PAUSE_STAGE"]
}
```

## Repair Explainability
Attempt 结果增加：
```json
{
  "failure_classification": "CONTACT_ONLY",
  "failure_codes": ["F11"],
  "selected_attempt2_route": "WF_MOUTH_REPAIR@v2",
  "route_reason": "MEASURED_UPLIFT_GE_8PP"
}
```

## Evidence
- `Event Hash Chain` 必须由真实 `operation_event` 顺序计算，不允许页面写死。
- Formal Evidence 显式展示 `manifest_sha256`、`object_lock_mode`、`retention_until`。
- 后端保存不可篡改对象版本，前端只负责展示验证状态。

## Gold Case
Gold Case 必须可展开到原始 Operator Test：
- operator_id
- center_error
- rotation_error
- scale_error
- expert_mask_used
- duration_seconds

## 产品边界
TCO / Lean / Platform 继续不进入业务系统 UI；作为实施治理材料单独维护。


# 15. 视觉与微交互冻结建议

本轮只做视觉保真和微交互，不新增业务功能。

## Data Visualization
- Repair Uplift 使用 Attempt 1 → After Repair 差值图。
- Bootstrap CI 使用 range bar。
- Placement Sensitivity 使用折线图 + 5% Gate 虚线。
- Failure Distribution 使用 Donut。

## Studio Feedback
- `INFERENCE_STARTED` 显示 spinner。
- `VALID_OUTPUT` 使用 1 秒成功闪烁。
- Placement 滑块根据 Safe / Edge / Unsafe 改变 accent color。
- Gold Overlay 显示偏差方向。

## Accessibility
- 全局 `:focus-visible` 使用品牌色 focus ring。
- Modal 打开时焦点进入第一个可交互元素。
- 小字最小提升到 11px。
- 移动端 Accuracy Grid 在 760px 以下切为 2 列，480px 以下单列。

## Review UI
- QC FAIL 卡片左上增加红点。
- Attempt 2 显示“Repair 生效”视觉标记。
- Advanced 操作统一降权，明确为例外路径。


# 16. SaaS 视觉层冻结

本版产品原型使用 B2B SaaS 后台风格：

- 浅色 Sidebar + Workspace Switcher；
- Topbar 全局搜索；
- 低阴影、细边框、12px Radius；
- 信息密度偏紧凑，不采用营销型大卡片；
- 状态 Badge、表格、Tabs、Config Editor 统一为 SaaS 控制台语义；
- 图像生成工作台保留深色 Canvas，外层仍保持 SaaS 管理界面；
- 不改变既有业务功能、状态机、Gate 与权限结构。

设计基调参考：
`Linear / Vercel / Notion / Figma Admin` 一类现代 B2B SaaS 产品，而不是官网 Landing Page。


## 16.1 视觉风格与页面结构的适用范围（2026-09-05 用户澄清）

企业 SaaS 是前端整体的视觉设计方向，不要求所有页面套用控制台布局。配色、字体层级、边框、圆角、间距及组件状态应保持一致；页面结构按实际使用场景设计。登录页是独立入口，仅包含品牌、登录表单和必要帮助，不放入侧栏、顶栏、工作空间切换或面包屑。控制台导航仅适用于登录后的工作界面。
